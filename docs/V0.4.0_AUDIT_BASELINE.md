## Known inconsistencies captured at baseline

These are the defects the v0.4 hardening program begins from:

- Version drift: `VERSION`/`pyproject.toml` = `0.4.0.dev0`,
  `construction_ai/__init__.py` = `0.3.0`, docs = `v0.3.0`,
  `requirements.lock.txt` header = `v0.3.0`, manifest = `0.3.0`.
- Accidental duplicate files: `construction_ai/reconstruction/graph_view 2.py`,
  `evaluation/corpora/__init__ 2.py`.
- Stale manifest includes cache artifacts.
- No human approver identity; API key represents an organization only.
- Caller-supplied `user_id` treated as approver identity.
- ERP supplier verification can be contaminated by invoice-derived state.
- Boolean-only verification; missing data can pass.
- Approval mutation is not atomic with audit append.
- Audit role retains UPDATE/DELETE/TRUNCATE.
- DB insert then Redis LPUSH has a split-brain window.
