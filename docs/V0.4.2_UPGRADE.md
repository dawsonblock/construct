# v0.4.2 Upgrade Gate — Verification Integrity

The second repair release. It closes the verification control failures: the ERP
supplier tautology, boolean-only checks that silently passed on missing data,
and caller-declared work completion.

## What changed

### ERP supplier independence (items 6, 7)
- `construction_ai/erp/supplier_resolution.py`: ERP supplier -> local company
  resolution with an explicit priority chain (ERP supplier ID, tax id, verified
  mapping, exact normalized name, fuzzy as suggestion only). Abstains on
  ambiguity; never merges.
- `migration 009`: `external_entity_mappings` (verified mappings, RLS).
- The pipeline resolves the PO/quote vendor **independently** from the supplier
  ERP actually returned — never copied from the invoice. `vendor_match` compares
  two independent resolutions. The canonical negative case (invoice ABC / ERP PO
  supplier XYZ) now fails closed to HOLD.

### ERP observations as first-class evidence (item 8)
- `ERPNextEvidenceResolver` produces `ERP_PURCHASE_ORDER_SNAPSHOT` and
  `ERP_QUOTE_SNAPSHOT` evidence (raw hash, normalized fields, adapter version,
  query). The pipeline persists them and references them from the approval;
  ERP results are no longer ephemeral Python values.

### Tri-state verification (items 9, 10, 11)
- `CheckStatus`: PASS / FAIL / UNAVAILABLE / ERROR / REVIEW_REQUIRED.
  Invariant: `MissingRequiredEvidence !=> PASS`. `VerificationResult` carries
  per-check provenance (observed, expected, evidence_ids, verifier_version).
- `tax_math`: Decimal arithmetic at currency-specific precision; missing
  subtotal/tax/total is UNAVAILABLE, not PASS.
- `currency_match`: invoice currency must equal PO currency; no automatic FX.
- `amount_match`: Decimal, currency-precise.

### Work confirmation as evidence (item 12)
- `migration 010`: `work_confirmations` table (RLS).
- `construction_ai/work/` package (models, repository, confirmation service).
- `work_confirmed` removed from the API request body; the pipeline derives it
  from `work_confirmations` records. New
  `POST /projects/{project_id}/work-confirmations` endpoint records completion.

## Out of scope (later releases)
- Progress billing (item 13) and contract/change-order authority (item 14).
